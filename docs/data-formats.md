# Data Formats

## Sector Layout (512 bytes)

Every data sector written by ZINF has the same structure:

```
Offset   Size   Field
------   ----   -----
0        1      Header byte  (caller-defined, e.g. 0x01 for sensor data)
1        507    Payload      (raw data bytes)
508      4      CRC32        (little-endian, covers bytes 0–507)
```

Total: 512 bytes = 1 + 507 + 4

The CRC covers both the header and the payload, so a corrupted header is also detectable.

## Log Metadata Sector (format v3 — 64-bit LBA)

The first sector (`log_sector`, default 0) stores log state. Its contents:

```
Offset   Size   Field
------   ----   -----
[Copy slot 0]
0        8      last_sector  — last written data LBA (uint64, little-endian)
8        2      version      — monotonic write counter (uint16, little-endian)

[Copy slot 1]
10       8      last_sector  (same fields, redundant copy)
18       2      version

[Copy slot 2]
20       8      last_sector  (same fields, redundant copy)
28       2      version

[Common fields]
30       2      write_pos    — current message log write position (uint16, little-endian)
32       1      flags        — reserved (0x00)
33     479      Message log data (first 479 bytes)
```

Constants (from `config.h`):

| Constant | Value | Description |
|---|---|---|
| `META_COPY_STRIDE` | `10` | Bytes per copy slot (8 LBA + 2 version) |
| `META_COPIES` | `3` | Redundant copy slots |
| `META_WRITE_POS_OFF` | `30` | Offset of `write_pos` field |
| `META_FLAGS_OFF` | `32` | Offset of `flags` byte |
| `META_HDR_SIZE` | `33` | Total header size; message log starts here |

The adjacent sector (`log_sector + 1`) holds the continuation of the message log:

```
Offset   Size   Field
------   ----   -----
0        512    Message log continuation (all 512 bytes)
```

Total message log capacity: 479 + 512 = **991 bytes** (`MSG_LOG_TOTAL_CAP`)

### Version Counter

Three copy slots each record the `last_sector` LBA and a monotonic 16-bit version counter.
On each metadata write, the next copy slot is chosen in round-robin order and its version incremented by one.
The slot with the highest version (using modular comparison to handle 0xFFFF → 0x0000 wraparound) is the authoritative copy.

## Sensor Wire Format (8 bytes)

`sensor_t` is serialized to 8 bytes by `sensor_t_to_wire()` (generated by `zinf_gen.py`):

```
Offset   Size   Field
------   ----   -----
0        4      temp      — float32, little-endian
4        4      humidity  — float32, little-endian
```

Example: temp = 23.5°C, humidity = 65.0%

```
hex: 00 00 BC 41   3E 83 82 42
     └── 23.5 ──┘  └── 65.0 ──┘
```

## RAID Physical Address Calculation

Given:
- `base_cursor` — sector index of the first chunk to write (= `last_log_index + 1`)
- `chunk_index` — 0-based index within the current write batch
- `mirror_num` — 0-based mirror index (0 … mirror_count-1)
- `mirror_offset` — stored in `zinf_ctx_t`, computed from device size

Physical sector address:

```
physical = base_cursor + chunk_index + mirror_num * mirror_offset
```

### Example (mirror_offset = 5119, base_cursor = 2)

| Chunk | Mirror 0 | Mirror 1 |
|---|---|---|
| 0 | 2 | 5121 |
| 1 | 3 | 5122 |
| 2 | 4 | 5123 |

## Full Sector Allocation Map

```
Sector          Purpose
------          -------
0               Log metadata (primary)   — 33-byte header + 479 bytes message log
1               Log metadata (secondary) — 512 bytes message log continuation
2 .. M-1        Data, Mirror 0
M .. end-1      Data, Mirror 1 (physical = logical + mirror_offset)
```

Where `M = 2 + mirror_offset` (first mirror 1 sector).

For a 5 MB device (10240 sectors, mirror_offset = 5119):

```
Sector 0         → metadata primary
Sector 1         → metadata secondary
Sectors 2..5120  → data mirror 0  (5119 data sectors)
Sectors 5121..10239 → data mirror 1  (5119 data sectors)
```

## Log Sector Initialization Values

After `init_log_sector()`, sector 0 contains:

```
[0..9]   Copy slot 0: last_sector=0 (8 bytes LE), version=0 (2 bytes LE)
[10..19] Copy slot 1: same zeros
[20..29] Copy slot 2: same zeros
[30..31] write_pos = 0 (2 bytes LE)
[32]     flags = 0x00
[33..511] 0x00 (empty message log)
```

Sector 1 is zeroed entirely.
