# ZINF Studio Usage Guide

ZINF Studio is the primary desktop appliance for researchers and hardware developers. It provides a high-readability "Retro Creamy" interface for managing ZINF-formatted devices, configuring data schemas, and generating integration code.

---

## 1. Explorer Tab
The Explorer is your primary interface for hardware data extraction and integrity verification.

### Hardware Sidebar
- **Connected Devices**: Shows a list of all detected ZINF-formatted block devices (including loop devices and SD cards).
- **Format Version**: Displays the ZINF version (e.g., v4) read from the device's metadata sector.
- **Refresh**: Use the scan button to re-poll the system for new hardware.

### Live Extraction
1. Select a device from the sidebar.
2. Click **[ Extract Data ]**.
3. Choose a destination for the exported `.csv` file.
4. Data will stream into the table in real-time. The UI limits the preview to 1000 rows to ensure smooth performance during large extractions.

### Offline Preview
You can view previously exported data without a hardware connection:
1. Click **[ Load Offline CSV ]** in the Explorer's empty state.
2. Select a `.csv` file generated by ZINF Studio.
3. The table will populate with the file's content, and the footer will indicate "OFFLINE PREVIEW" mode.

### Integrity Verification (Scrubbing)
Click **[ Verify Integrity ]** to perform a full-range scrub of the selected device. This process:
- Scans all RAID mirrors.
- Automatically repairs single-mirror corruption.
- Reports the count of Healthy, Repaired, and Unrecoverable sectors in the footer bar.

---

## 2. Configurator Tab
The Configurator manages the `zinf.yaml` master configuration.

### Bidirectional Synchronization
- **Visual Editor**: Use sliders and dropdowns to adjust redundancy (`mirror_count`), sector geometry, and metadata allocation.
- **Raw YAML (v4)**: Directly edit the YAML text for advanced control. Changes are synced instantly between both views.

### Data Schema Editor
- **Add Structs**: Create new data types using the **[ + ]** button in the Data Schemas panel.
- **Wire Fields**: Define fields (name and type) for each struct. Supported types include `float`, `double`, `i16`, `u16`, `i32`, `u32`, and `u8`.
- **Regenerate**: Click **[ Regenerate C API ]** to save your changes to `zinf.yaml` and trigger the code generator, updating the project's C headers and sources.

---

## 3. SDK Generator Tab
The SDK Generator assists developers in integrating ZINF into custom MCU firmware.

### Integration Wizard
1. Enter a **Hardware ID** (e.g., `bme280`) and select your **Bus Protocol** (SPI, I2C, UART).
2. Click **[ Create SDK Package ]**.
3. A tabbed code viewer will display the generated C templates (`main.c`, `driver.h`, etc.).

### Compiler Guards
The generated code includes mandatory `#error` pragmas. These guards act as a step-by-step checklist, ensuring you don't skip critical initialization or bus-read implementation steps during integration.

### Module Sandbox
The **Sandbox** tab provides a mock desktop environment. You can test your sensor-parsing logic on a Linux PC by simulating raw bus bytes before cross-compiling for your target MCU.
